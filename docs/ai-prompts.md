# AI Prompt 使用清单（VS 工作区 · 假发试戴 MVP 专版）

> 使用方式：找到对应场景 → 复制 → 粘贴到 Cursor Chat → 改【】内的内容 → 发送。
> 工作区结构：`wig-tryon-backend/`（Spring Boot）+ `ai-hairstyle-mini-program-ui/`（React + Vite）。

---

## 🟦 场景 1：接到新需求（用 Plan 模式 / Shift+Tab 切换）

```
我接到了一个新需求，请先帮我做分析，不要写任何代码。

【需求描述】
在这里粘贴你的需求文字

【涉及范围】（勾选）
- [ ] 后端（wig-tryon-backend）
- [ ] 前端（ai-hairstyle-mini-program-ui）
- [ ] AI 模型 / Prompt（PromptBuilder / DashScopeAiService）
- [ ] 跨端联调

请按以下结构输出：
1. 一句话目标
2. 业务对象（涉及哪些核心实体：Session / WigProduct / TryonTask / FaceAnalysisResult 等）
3. 主流程（最多 7 步，标清前端 / 后端 / AI 调用）
4. 异常流程（至少 3 个：session 过期、AI 失败、网络断开、Key 缺失……）
5. 涉及的文件或模块（精确到类名 / 组件名）
6. 三模式（real / seed / mock）下分别如何表现
7. 描述不清楚的歧义点
8. 技术风险点（成本、稳定性、隐私、向后兼容）
9. 最小可交付版本是什么

分析完成后等我确认，不要自动开始写代码。
```

## 🟩 场景 2：开始写代码（用 Agent 模式）

```
需求分析已确认，现在开始实现。

【本次只实现】
说明这次只实现哪一层 / 哪一块，例如：
"只在 PromptBuilder.tryonPrompt 里新增「短发显瘦」分支，并补 LOCAL_SHORTEN 试戴类型"

【相关代码文件】
@文件名1
@文件名2

【实现约束】
- 优先最小改动；保持现有代码风格
- 不引入新依赖（前端不要加路由/状态库，后端不要加 MyBatis/JPA/Lombok）
- AiService 接口任何改动必须同步 mock / seed / dashscope 三实现
- 离线降级分支不允许删除
- 关键决策必须加注释说明"为什么这样写"

请先输出：
1. 计划修改的文件清单
2. 实现思路（3~5 句话）
3. 三模式（real / seed / mock）行为预期
4. 你发现的潜在风险

等我确认后再开始写代码。
```

## 🟨 场景 3：看不懂一段代码（用 Ask 模式）

```
请帮我理解以下代码，要精准，不要泛泛而谈。

【代码】
@文件名 或直接粘贴代码

请按以下结构输出：
1. 这段代码解决了什么问题（1 句话）
2. 输入是什么，输出是什么（含类型）
3. 数据怎么流动（关键步骤，标清是否跨进程 / 跨服务 / 调外部 API）
4. 关键分支（重要 if/else / try/catch）
5. 异常处理是否合理，是否有降级路径
6. 如果这里出 Bug，最可能在哪几行，为什么
7. 如果我要改【你想改的功能】，应该先看哪些方法

最后用 1 句话总结核心逻辑。
```

## 🟥 场景 4：修 Bug（用 Debug 模式）

```
我遇到了一个 Bug，请帮我分析，不要直接重写代码。

【现象描述】
描述 Bug 表现，例如：
"试戴效果墙一直停在 30% 不动，复现概率 100%；切到 seed 模式正常"

【环境信息】
- AI_MODE：real / seed / mock
- 是否配置 DASHSCOPE_API_KEY：是 / 否
- 前端是否走 Vite 代理：是 / 否
- 浏览器控制台 / 后端日志 关键片段

【错误堆栈 / 关键日志】
粘贴完整 stacktrace 或 log

【相关代码】
@文件名

【我自己的初步判断】
我认为问题可能在 XXX，但不确定

请按以下格式输出：
1. 根因假设（最多 3 个，从最可能到最不可能）
2. 每个假设的验证方式（加什么日志 / 断点 / 切哪个模式复现）
3. 等我确认根因后，再给最小修复方案
4. 需要补充哪些回归测试

在我确认根因之前，不要开始改代码。
```

## 🟣 场景 5：代码审查（用 Ask 模式）

```
请以严格代码审查员的身份检查以下代码。

【代码】
@文件名 或粘贴代码

【代码定位】（勾选）
- [ ] 后端 controller / service / repository
- [ ] AI 抽象层（AiService / PromptBuilder / Router）
- [ ] 前端组件 / hook / api client

请从以下维度逐一检查，每个维度都必须给出明确结论：
1. 空指针 / undefined 风险（在哪里）
2. 线程安全 / 并发问题（后端：tryonExecutor / SessionRepository）
3. 异常处理是否完整（含三模式降级是否被破坏）
4. SQL 注入 / SSRF / 越权风险（即便目前用内存仓库）
5. 性能问题（轮询超时、N 次 fetch、大对象、base64 重复编码）
6. 日志是否合理（不打 API Key、不打用户原图 base64、错误堆栈完整）
7. 离线演示是否仍可走通（sessionId=null / 后端关掉）
8. 是否破坏既有接口契约（前后端类型 / ApiResponse 结构）

输出格式：
🔴 严重问题（必须修）：问题描述 + 文件:行 + 如何修
🟡 中等问题（建议修）：问题描述 + 建议
🟢 优化建议（可选）：
✅ 做得好的地方：

只给建议，不要直接修改代码。
```

## 🟤 场景 6：写汇报文档 / 周报（用 Agent 模式）

```
请帮我写一份工作汇报，要求简洁务实，不说废话。

【基本信息】
- 汇报对象：研发经理 / 客户 / 技术总监
- 汇报类型：周报 / 项目阶段 / 客户 demo 复盘
- 风格：结论优先，尽量量化，不超过 500 字

【素材】
已完成：
- 例如：完成上传 → 推荐 → 效果墙主流程，新增 LOCAL_HAIRLINE 试戴类型
- 例如：DashScope wanx2.1-imageedit 联调通过

遇到问题：
- 例如：本地 URL 无法被 DashScope 拉取，改为 data URI 自传

风险：
- 例如：真实模式单次试戴成本 X 元，需评估上线计费策略

下周计划：
- 计划 1

请先输出提纲，我确认后再展开正文。
最后另输出一个【100 字摘要版本】用于直接粘贴到群里。
```

## ⚫ 场景 7：客户 Demo PPT / 介绍页（用 Agent 模式）

> 这个场景对应 `interactive-mvp-presentation-html`，那个目录目前几乎为空，可以从头按下面 prompt 生成大纲。

```
请把以下内容转成给客户做 demo 的 PPT 大纲，我自己来落地（HTML 或 Keynote）。

【基本信息】
- 听众：客户决策人（非技术）
- 目标：说服客户继续推进项目 / 锁定 MVP 验收
- 总页数：10 页以内
- 风格：少字、多图、结论先行

【内容素材】
- 客户痛点（白发 / M 型发际线 / 蜡像感 / 价格区间）→ 我们的方案
- 上传 → 推荐 → 试戴 → 调整 → 门店转化 主流程截图
- 三模式（real / seed / mock）的现场演示策略
- 数据看板（funnel / 试戴完成率 / 咨询率）
- 后续 4 周计划

每页请输出：
1. 页标题（6 字以内）
2. 3~5 个核心要点（每条 15 字以内）
3. 建议配什么图或截图（指明取自哪个页面 / 哪个流程节点）
4. 演讲备注（你要说的话，2~3 句）

先给我第 1~3 页，确认方向后再继续。
```

## 🔵 场景 8：读懂某条调用链（用 Ask 模式）

```
我需要快速了解这个项目的某条调用链，请帮我梳理。

【涉及文件】
@前端入口（如 UploadPage.tsx / TryonWallPage.tsx）
@后端 controller（如 PhotoController.java）
@后端 service（如 TryonService.java）
@AI 实现（如 DashScopeAiService.java）

【我想了解的链路】
例如：从用户点击"开始试戴"到效果图出现在效果墙的完整过程

请输出：
1. 调用链（前端组件 → fetch → controller → service → AI → 回写状态 → 前端轮询 → 渲染）
2. 数据流（FaceAnalysisResult / TryonTask / GenResult 怎么演变）
3. 状态变化（TryonTask.Status: PENDING → PROCESSING → SUCCESS / FAILED）
4. 三模式（real / seed / mock）在哪一步分叉
5. 异常 / 降级路径（每一层失败时落到哪）
6. 改这个功能最应该先看的 3 个方法
7. 最容易出 Bug 的位置

最后给我一个【文字版时序图】，用箭头表示前后端 + 线程切换。
```

## 🟠 场景 9：AI Prompt 调优（项目专属）

```
我要调整 PromptBuilder 里的【哪个 prompt】，请先评估再改。

【调整目标】
例如：把刘海效果做得更"蓬"，目前生成的刘海偏贴头皮

【现状】
@wig-tryon-backend/src/main/java/com/wig/tryon/service/ai/PromptBuilder.java

【约束】（不允许删除）
- 脸型/五官/肤色保持不变
- 消蜡像感、发丝真实
- 既有 LOCAL_BANGS / LOCAL_HAIRLINE 分支
- 中文 prompt（国产模型友好）

请输出：
1. 你打算改 PromptBuilder 的哪几个方法 / 哪几行
2. 改动前后的 prompt 对比（diff）
3. 为什么这样改（基于哪条 prompt engineering 经验）
4. 验证步骤：切到 AI_MODE=real，跑哪几款产品 + 哪几张照片
5. 风险：会不会让"全头套"或"自然直发"效果变差

等我确认后再改代码。
```

## ⚠️ 三个最重要的使用习惯

1. **新任务先 Plan 再 Agent**：复杂改动用场景 1 拿到计划，确认后再切 Agent 用场景 2。
2. **每次 AI 改完先看 diff**：不管 AI 怎么说，都要打开 diff 视图逐文件确认。
3. **规则是活文档**：AI 反复犯同样错误时，问它"请建议我把什么补进 `.cursor/rules/*.mdc`"，然后真的加进去。
