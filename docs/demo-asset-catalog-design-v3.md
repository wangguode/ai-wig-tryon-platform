## 0. 一句话理解

在客户素材库中，把 **假发本体（静物/_C 产品图）** 与 **模特佩戴图（IMG_/棚拍人像）** 严格拆开入库；C 端只看后者，试戴 AI 只用前者 + 用户自拍；并按短发/中长发/长发/卷发扩量，每款 10~15 张、跨 2~4 个不同模特。

## 1. 现状诊断（为什么领导会觉得「都一样」）

| 问题 | 现状 | 影响 |
|---|---|---|
| 陈列与本体未严格分离 | v2 导入把同文件夹 `_C` 图既当 `WigAsset.productImage` 又进 `gallery` | 部分「商品图」其实是静物，视觉单调 |
| 模特关联缺失 | 327 条 showcase 的 `modelAssetId` **全部为 null** | 无法讲清「多模特展示」、后台工坊显示 `#null` |
| 分类不均衡 | 31 款：短发 8 / 中长发 6 / 长发 6 / 卷发 11 | 长发、中长发偏少 |
| 大库未用 | `摄影师拍摄静物原图C` 226 张、`摄影师拍摄模特原图C` 2413 张未结构化接入 | 扩量空间巨大但缺配对规则 |
| AI 推理路径 | `TryonService` **已正确**走 `wigAsset.productImage` | 代码层 OK，**数据层**需对齐 |

**结论**：今天要修的是 **导入规则 + 模特池 + 分类扩量**，不是重写试戴服务。

## 2. 核心数据模型（展示 vs 推理）

```
┌─────────────────────────────────────────────────────────────────┐
│  WigAsset（① 假发本体）                                          │
│  productImage = 静物/白底/_C 产品图（无完整人脸）                   │
│  descriptionForAi = 长度/卷度/刘海/颜色…                          │
└───────────────┬─────────────────────────────────────────────────┘
                │ 1 : N
                ▼
┌─────────────────────────────────────────────────────────────────┐
│  WigShowcase（③ 陈列成品）                                       │
│  resultImage = 模特佩戴该款假发的棚拍图                           │
│  wigAssetId  → ①                                                │
│  modelAssetId → ②（必填，演示版至少按规则填充）                   │
│  isPrimary   → 该款 C 端封面                                     │
└───────────────┬─────────────────────────────────────────────────┘
                │ N : 1（封面）
                ▼
┌─────────────────────────────────────────────────────────────────┐
│  WigProduct（④ 上架商品）                                        │
│  wigAssetId → ①（AI 唯一参考来源）                               │
│  image / galleryImages ← 来自 ③（RecommendService 注入）         │
└─────────────────────────────────────────────────────────────────┘

用户试戴（C 端）：
  用户自拍 + ①.productImage + descriptionForAi → AI → UserTryon
  （③ 陈列图 不参与推理）

运营预生产（可选）：
  ②.portraitImage + ①.productImage → AI → ③
```

**硬约束（与项目规则一致）**：
- `TryonService` 只读 `WigAsset.productImage`，禁止把 showcase 当参考图
- `RecommendService.enrichWithShowcase` 只把 ③ 填进 `image` / `galleryImages`
- 三模式降级：`seed` 缺本体时 WARN + 回退，不删 `seed` 生命线

## 3. 客户素材文件分类规则（导入 v3 核心）

### 3.1 V 系列文件夹（最可靠，优先）

| 类型 | 文件名模式 | 入库目标 |
|---|---|---|
| **本体** | `正_C` / `0_C` / `1_C` / `后_C` / `0F6Axxxx_C`（非 IMG） | `WigAsset.productImage`（优先级：正_C > 0_C > 1_C > 其它 _C） |
| **陈列** | `IMG_*` 或文件名含 `IMG` 的棚拍人像 | `WigShowcase.resultImage` |
| **排除** | `*副本*`、与本体同文件的重复项 | 跳过 |

每款目标：**1 张本体 + 10~15 张陈列**（陈列仅来自 IMG 类）。

### 3.2 设计师款 / Art 系列（次优）

- 文件夹内多为「已佩戴」棚拍，**不一定有独立静物**
- 规则：
  1. 若 chunk 内含 `_C` 且画面为静物/产品（文件名 `0F6A*_C` 优先）→ 本体
  2. 其余 → 陈列
  3. 若 chunk **全无静物** → 从 `摄影师拍摄静物原图C` 按 **category 轮询** 分配一张作本体（记录 `sourceNote=still-life-pool`，演示可说明「同系列静物代表」）

### 3.3 大库扩量（P1，演示加分项）

`静物 226` 与 `模特 2412` **文件名无交集**，不能自动 SKU 配对。

扩量策略（二选一，见 §5 方案对比）：
- **保守**：仅 V 系列 + 设计师/Art 重新分类（快，2h 内）
- **积极**：人工/半自动「类别包」——按运营标注的 category 从两库各抽 N 张组成虚拟「款式包」（慢，质量需抽检）

## 4. 模特池 & 「每类不同模特」

### 4.1 ModelAsset 目标池（演示版 12 人）

| ID 段 | 性别 | 年龄段 | 脸型标签 | 用途 |
|---|---|---|---|---|
| M01~M03 | F | young | 圆脸/鹅蛋/长脸 | 短发/卷发陈列 |
| M04~M06 | F | mid | 方脸/鹅蛋/瓜子 | 中长发/长发 |
| M07~M08 | F | elder | 圆脸/长脸 | 银发/遮白演示 |
| M09~M10 | M | young/mid | 方脸/长脸 | 中性短发 |
| M11~M12 | F | young | 多样 | Art/设计款 |

**肖像来源**（按优先级）：
1. 各 V 文件夹 `IMG_*` 各取 1 张代表图（同文件夹 IMG 视为同一模特）
2. 不足时从 `摄影师拍摄模特原图C` 按文件名 hash 分散抽取

### 4.2 Showcase → Model 绑定规则

```
对每个 WigShowcase：
  if 来源文件是 IMG_*：
      modelAssetId = folderModelMap[所属文件夹]   // 同拍摄批次同模特
  else if 来源是设计师/Art 图：
      modelAssetId = categoryModelRotate[category] // 按类别轮询，保证同类不同款见到不同模特
```

**每款目标**：10~15 张陈列中 **至少 2~4 个不同 modelAssetId**（V 系列若 IMG 仅 5 张同模特，则跨款轮换不同文件夹模特补足「库内多样性」）。

## 5. 三方案对比（今日演示）

| 维度 | **方案 A：导入修准（推荐）** | 方案 B：导入 + AI 现生成 showcase | 方案 C：大库全自动扩量 |
|---|---|---|---|
| 做法 | v3 脚本重跑：本体/陈列分离 + 填 modelAssetId + 重平衡分类标签 | A 基础上，后台 Showcase Studio 对缺图款 AI 补生成 | 静物+模特大库自动组款 |
| 耗时 | **2~3 小时** | 4~8 小时（受 API 限速） | 1~2 天 + 质检 |
| 演示风险 | 低 | 中（API 失败/503） | 高（配对错误） |
| 领导可讲性 | ★★★★★ 数据链路清晰 | ★★★★ 可演示「AI 生产」 | ★★ 难解释来源 |
| 素材规模 | 31 款 → 分类调优；陈列 ~350 张 | 同左 + 部分 AI 新图 | 50~100+ 款 |
| **推荐** | **今日 P0** | 时间充裕时叠加 | 演示后迭代 |

**推荐：方案 A**，演示前留 30 分钟做 2 个「短发 + 1 个长发」真实试戴抽检。

## 7. C 端 & 后台展示（演示脚本）

### 7.1 小程序（领导主视角）

1. 试戴墙 → 系列 chip（V系列/设计款/Art款）+ 分类 chip（短发/长发/卷发）
2. 点进某款 → **款式素材画廊** 10~15 张（不同模特脸型）
3. 上传自拍 → 选款试戴 → 强调：「生成时用的是 **假发本体**，不是上面这些模特图」

### 7.2 运营后台（可选 3 分钟）

路径：`http://localhost:5173/#admin` → 成品图工坊

讲法三连：
1. **假发本体**页：白底/静物 `_C` 图
2. **模特库**：12 位模特肖像
3. **某款 showcase 列表**：每条带 `wigAssetId` + `modelAssetId`，主图 = C 端封面

Dashboard 数字目标：`31 本体 / 12 模特 / 327+ showcase / showcase 100% 有 modelAssetId`
